# iOS Linux Development Setup (xtool) — Design Spec

**Date:** 2026-05-20  
**Branch:** `feature/linux-xtool-dev`  
**Scope:** Full local dev workflow for `ios-app/` on Linux using xtool — edit Swift code, get build feedback, deploy to device.

---

## Context

The `ios-app/` project is a SwiftUI + GRDB.swift app targeting iOS 17+. It has a single Swift Package dependency (GRDB 6.29.3). The existing workflow requires Xcode on macOS. This spec covers adding a parallel Linux workflow using [xtool](https://github.com/saagarjha/xtool) so developers can edit and build from a Linux machine.

A Mac is available (the development machine) for one-time SDK extraction.

---

## File Structure

Everything lives under `ios-app/linux-dev/`. Nothing in this directory is committed except scripts and docs — the SDK tarball is tracked via Git LFS.

```
ios-app/
  linux-dev/
    extract-sdk.sh      # run once on Mac — packages iOS SDK from Xcode
    setup-linux.sh      # run once on Linux — installs Swift, xtool, unpacks SDK
    Makefile            # daily workflow: make build / make install / make clean
    LINUX_DEV.md        # setup guide and daily workflow docs
```

`ios-app/.gitignore` gets an entry for `linux-dev/*.tar.gz` as a safety fallback (LFS handles the tracked file, this prevents accidental non-LFS commits of other tarballs).

---

## SDK Distribution — Git LFS

The iOS SDK tarball (~400–600 MB) is stored in Git LFS so the repo history stays lean. Anyone cloning the repo with `git lfs pull` gets the SDK automatically.

- Git LFS is initialised at repo root on first setup
- The pattern `ios-app/linux-dev/SignalArchive-ios-sdk.tar.gz` is tracked via LFS
- The tarball is regenerated by re-running `extract-sdk.sh` after Xcode updates

---

## Mac-Side: `extract-sdk.sh`

Run once on macOS (or after a major Xcode update).

**Steps:**
1. Resolve the active Xcode developer directory via `xcode-select -p`
2. Locate the iOS SDK at `$DEVELOPER_DIR/Platforms/iPhoneOS.platform/Developer/SDKs/iPhoneOS.sdk`
3. Verify the SDK version is 17.0+; exit with a clear error if not found
4. Package with `tar -czf ios-app/linux-dev/SignalArchive-ios-sdk.tar.gz -C <sdk-parent> iPhoneOS.sdk`
5. Print Xcode version, SDK path, and tarball size on completion

**Output:** `ios-app/linux-dev/SignalArchive-ios-sdk.tar.gz`

---

## Linux-Side: `setup-linux.sh`

Run once on the Linux development machine.

**Steps:**
1. Detect Linux distro (Ubuntu 22.04/24.04 or Fedora) and install the Swift 5.10 toolchain from swift.org's official package
2. Clone `saagarjha/xtool` and build with `swift build -c release`; install binary to `~/.local/bin/xtool`
3. Unpack `SignalArchive-ios-sdk.tar.gz` to `~/.local/share/xtool/sdks/iPhoneOS17.sdk`
4. Write `~/.config/xtool/config` with the SDK path
5. Prompt the user to authenticate with their Apple ID (xtool's interactive sign-in handles provisioning/signing)

**Prerequisites on Linux:** `git`, `curl`, `tar`, internet access, USB access for device deployment.

## Daily Workflow: `Makefile`

| Target | Command | Description |
|--------|---------|-------------|
| `make build` | `xtool build` | Compile the app; resolve GRDB via SPM; print errors |
| `make install` | `xtool install` | Deploy signed IPA to USB-connected device |
| `make clean` | `xtool clean` | Remove derived data for this project |
| `make resolve` | `xtool resolve` | Re-fetch SPM dependencies without building |

The Makefile is run from `ios-app/linux-dev/` and references the project at `../SignalArchive.xcodeproj`.

## Documentation: `LINUX_DEV.md`

Covers:
- Prerequisites (Swift, xtool, Apple Developer account)
- One-time Mac setup (running `extract-sdk.sh`, committing via LFS)
- One-time Linux setup (running `setup-linux.sh`, Apple ID auth)
- Daily workflow (`make build` → edit → `make build` → `make install`)
- Updating the SDK after an Xcode upgrade
- Troubleshooting (common xtool errors, signing issues, device not found)

---

## What's Not Covered

- Simulator support on Linux (no iOS simulator outside macOS)
- SwiftUI previews (Xcode-only)
- CI pipeline (this spec is for local dev only)
- Windows support
